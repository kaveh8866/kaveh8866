# تصمیم معماری ADR-Q001 — ورودی API در برابر تحلیل جریان و ذخیره‌سازی دائمی

[English](decision.en.md) · **وضعیت: تصمیم آموزشی، نه معماری آماده تولید**

## زمینه

در صورت مسئله بازنویسی‌شده، یک شرکت اشتراک دوچرخه به ثبت موقعیت در ساعات اوج، اتصال به سامانه تحلیل و دریافت داده از REST API نیاز دارد. گزینه‌ها: Athena + S3؛ API Gateway + Lambda؛ QuickSight + Redshift؛ API Gateway + Kinesis Data Analytics (نام جدید: Amazon Managed Service for Apache Flink). در تصویر گزینه D سبز است، اما **رنگ گزینه به‌تنهایی اثبات پاسخ رسمی نیست**.

## تصمیم‌ها و محدودیت‌ها

۱. **برای کوچک‌ترین آزمایش ورودی:** **API Gateway HTTP API + AWS Lambda** را انتخاب می‌کنیم؛ مسیریابی، اعتبارسنجی ورودی، Integration، IAM و Logging را یاد می‌گیریم.

۲. **بدون ذخیره‌سازی دائمی:** پاسخ تابع `stored=false` دارد؛ بازیابی تاریخچه **پیاده‌سازی نشده**. CloudWatch Log دیتابیس تجاری موقعیت نیست.

۳. **در معماری کامل:** می‌توان DynamoDB یا پایگاه داده مناسب را برای نوشتن/خواندن افزود؛ برای تحلیل جریان گسترده نیز Kinesis Data Streams و Managed Service for Apache Flink همراه یک مقصد تحلیلی مطرح می‌شوند. این سرویس‌ها **در این کیت ایجاد نمی‌شوند**.

۴. **ابهام سؤال آزمونی:** هیچ‌یک از گزینه‌های دوتایی لزوماً هر سه قابلیت ورودی REST، ذخیره‌سازی دائمی و بازیابی فوری تاریخچه را به‌تنهایی فراهم نمی‌کند. Flink پایگاه داده عملیاتی ماندگار نیست و Lambda هم به‌خودی‌خود داده را ذخیره نمی‌کند. منبع سؤال را بررسی می‌کنیم و به‌جای اعلام قطعیت بی‌مدرک، ابهام را ثبت می‌کنیم.

## علت ناکافی‌بودن گزینه‌ها برای همان رابط

- **Athena + S3:** مناسب تحلیل داده‌های ذخیره‌شده؛ نه API عملیاتی آماده برای ثبت لحظه‌ای.
- **QuickSight + Redshift:** گزارش و انبار داده؛ نه رابط دریافت GPS.
- **API Gateway + Flink:** درگاه و موتور پردازش جریان؛ همچنان نیازمند منبع جریان و مقصد داده است.
- **API Gateway + Lambda:** مناسب ورودی و تبدیل داده؛ ولی برای راهکار کامل نیازمند ذخیره‌ساز است.

## ملاک آزمایش

درخواست امضاشده → 202؛ JSON نامعتبر → 400؛ مختصات نامعتبر → 422؛ درخواست بدون امضا → 401/403؛ هیچ موقعیتی ذخیره نشود. پاک‌سازی نبود منابع آزمایش را اثبات کند.

## محدودیت‌ها

این لَب نرم‌افزار کامل دوچرخه نیست. HTTP API و REST API سرویس API Gateway از نظر امکانات و هزینه تفاوت دارند. دامنه اصلی آزمون D3 است و D1/D2/D4 جنبه فرعی دارند. از این آزمایش کوچک نمی‌توان ظرفیت واقعی ترافیک یا ذخیره‌سازی یک محصول را نتیجه گرفت.
