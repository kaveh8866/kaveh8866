# سؤال ۰۰۱ — چرا آزمایش از معماری سؤال کوچک‌تر است؟

[English](cost-comparison.en.md) · [گردش تمام سرویس‌ها](service-tour.fa.md)

این کیت **در گزینه‌های آزمون، Lambda را جایگزین Kinesis نمی‌کند**. فقط یک *آزمایش آموزشی مستقل و حداقلی* انتخاب می‌کند تا API و Lambda را امن و سریع بشناسیم؛ درعین‌حال، **تمام سرویس‌های سؤال و دیاگرام تو، از جمله Kinesis و Flink، در مسیر گردش کنسول حضور دارند.**

## سه مسیر مشخص

**مسیر صفر — فقط مشاهده (بدون منابع ایجادشده توسط کیت):** از هر هشت سرویس دیدن کن و دو دیاگرام مرجع/آزمایش را رسم کن. این مسیر به معنی صفر بودن هزینه کل حساب AWS نیست.

**مسیر یک — میکرو-لب زنده کوچک (کم‌مصرف ولی نه الزاماً رایگان):** HTTP API حفاظت‌شده با IAM، تابع Python Lambda و CloudWatch. یک تا پنج درخواست ساختگی بفرست و همه منابع را حذف کن. **علت انتخاب Lambda:** برای یادگیری اتصال درخواست HTTP و حذف سریع، ساختار ساده‌تری داریم؛ **نه** به این معنی که Lambda جانشین تحلیل جریان Flink است.

**مسیر دو — معماری مرجع کامل (پیش‌فرض: صرفاً طراحی):** API Gateway → Kinesis Data Streams → Managed Service for Apache Flink → مقصد تحلیلی. اگر تاریخچه واقعی موقعیت نیاز است، ذخیره‌ساز عملیاتی و API خواندن نیز لازم است. این مسیر در آغاز گران‌تر و پیچیده‌تر است؛ بنابراین به‌جای اجرای پیش‌فرض، از [راهنمای بازدید کنسول](service-tour.fa.md) استفاده می‌کنیم.

## منطق هزینه، بدون ساختن عدد خیالی

- **مسیر صفر:** کیت منبع یا درخواست سرویس جدیدی جز مشاهده کنسول ایجاد نمی‌کند؛ هزینه منابع قبلی حساب را پوشش نمی‌دهد.
- **مسیر یک:** هزینه تابع تعداد فراخوانی API، زمان و تعداد اجرای Lambda و میزان CloudWatch Logs است. ممکن است اعتبار یا سهمیه حساب هزینه را پوشش بدهد، اما **صفر تضمینی نیست**.
- **مسیر دو:** علاوه بر هزینه API، زمان فعال‌بودن Stream و حجم داده، اجرای KPU در Flink، حداقل ده دقیقه صورت‌حساب هر شروع و ذخیره‌سازی برنامه/مقصد را در نظر بگیر. حتی Stream کم‌مصرف هم ممکن است هزینه زمانی داشته باشد.

**این جدول مقایسه مدل‌های صورتحساب و ریسک است، نه قیمت دقیق آلمان یا Region مشخص.** برای مبلغ دقیق، Region و نوع حساب را انتخاب کن و AWS Pricing Calculator را با شرایط واقعی و اعتبار موجود بررسی کن.
