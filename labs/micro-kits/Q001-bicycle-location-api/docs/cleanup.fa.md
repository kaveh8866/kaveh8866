# سؤال ۰۰۱ — راهنمای حذف و تأیید پاک‌سازی

[English](cleanup.en.md) · [پیش‌بررسی](preflight.fa.md)

تا وقتی **هم آزمایش و هم حذف منابع** تأیید نشده، لَب کامل نیست. ادعای «هزینه صفر» بدون بررسی Billing معتبر نیست؛ داده‌های مصرف ممکن است با تأخیر ثبت شوند.

## مسیر الف — منابع ساخته‌شده به‌صورت دستی

همان **Region** زمان ایجاد را انتخاب کن:

1. در **API Gateway → APIs** فقط API با نام `aws-micro-q001-manual-http` را پیدا کن. Stage و API را حذف کن و نبود آن را تأیید کن؛ اگر Domain اختصاصی یا گروه لاگ API ساخته‌ای، جدا بررسی کن.
2. در **Lambda → Functions** تابع `aws-micro-q001-manual-receiver` را حذف کن و نبود آن را دوباره بررسی کن.
3. در **CloudWatch → Logs → Log groups** گروه `/aws/lambda/aws-micro-q001-manual-receiver` را حذف کن. حذف Lambda لزوماً گروه لاگ را حذف نمی‌کند.
4. در **IAM → Roles** فقط نقش اختصاصی همین آزمایش را حذف کن (نام دقیقش را هنگام ساخت یادداشت کرده‌ای). اگر لازم است ابتدا Policy پایه را Detach کن. نقش مشترک را حذف نکن.
5. اگر برای فراخوانی API به هویت خود مجوز `execute-api:Invoke` اختصاصی افزوده‌ای، فقط همان Policy یا بند ویژه این آزمایش را بردار.
6. دوباره API Gateway، Lambda، CloudWatch و IAM را بررسی کن و با نام‌ها و تگ‌ها دنبال منابع باقی‌مانده بگرد.

## مسیر ب — منابع مدیریت‌شده با Terraform

در پوشه `terraform/` همین کیت، با **همان State، Workspace، حساب و Region** که Apply شده:


<pre dir="ltr" align="left"><code>terraform plan -destroy
terraform destroy
terraform state list</code></pre>


بعد از Destroy نباید منبعی از این کیت در State باقی مانده باشد. **پاک‌کردن فایل `.tfstate` منابع Cloud را حذف نمی‌کند.** اگر State گم شده، بدون بررسی دوباره Apply نکن و منابع دیگر را کورکورانه پاک نکن.

در کنسول مستقل بررسی کن:
- API Gateway: نام `aws-micro-q001-http` وجود ندارد.
- Lambda: تابع `aws-micro-q001-receiver` وجود ندارد.
- CloudWatch: گروه لاگ `/aws/lambda/aws-micro-q001-receiver` وجود ندارد.
- IAM: نقش `aws-micro-q001-lambda-role` وجود ندارد.
- Region درست باشد؛ دیگر منابع را با لیست اولیه مقایسه کن.

**اگر منبعی باقی ماند:** نام و خطای آن را خصوصی ثبت کن، پاک‌سازی را موفق علامت نزن و پیش از هر حذف هدفمند مالکیت/State را بررسی کن. هزینه غیرمنتظره را پس از تأخیر ثبت مصرف از Billing/Cost Explorer دنبال کن.

## شواهدی که ثبت می‌کنیم

- تاریخ، Region و مسیر **Manual** یا **Terraform**.
- پاسخ‌های HTTP بدون داده حساس، تست‌های محلی و سرویس‌هایی که نبودشان تأیید شده (شناسه‌های حساب را حذف کن).
- آیا همه منابع حذف شدند؟ بله/خیر؛ اگر خیر، چه چیزی باقی مانده؟
- بررسی بعدی Billing انجام‌شده یا در انتظار؟
- اسکرین‌شات‌های بدون شماره حساب، امضا، کلید یا داده شخصی.

**هیچ فایل این مخزن به‌صورت خودکار منابع حساب AWS تو را پاک نمی‌کند؛ اجرای واقعی مراحل ضروری است.**
