# استاندارد نگارش دوزبانه و راست‌به‌چپ Micro-Lab — نسخه ۱.۱

[English](BILINGUAL_MARKDOWN_STANDARD.en.md)

این قرارداد برای **تمام کیت‌های بعدی AWS** در این مخزن الزامی است.

## نام‌گذاری و معادل‌بودن محتوا

- هر صفحه انگلیسی مانند `README.md`، `manual.en.md` و `cleanup.en.md` معادل کامل `README.fa.md`، `manual.fa.md` و `cleanup.fa.md` دارد.
- نسخه فارسی و انگلیسی باید **هدف‌ها، مراحل دستی، محدودیت‌های امنیتی، هزینه، مقایسه معماری و پاک‌سازی یکسان** داشته باشند.
- هر فایل `.fa.md` در ابتدای خود `<div dir="rtl" align="right">` و در انتها `</div>` دارد. بین این برچسب‌ها و Markdown خط خالی قرار می‌دهیم تا GitHub تیتر و فهرست را درست پردازش کند.
- کد چندخطی یا دستور Shell باید در بلوک HTML با **جهت چپ‌به‌راست** قرار بگیرد: `<pre dir="ltr" align="left"><code> ... </code></pre>`؛ کاراکترهای HTML داخل کد باید Escape شوند. نام سرویس‌ها و کد کوتاه با Backtick نوشته شوند.
- جدول‌ها و لیست‌ها جهت را از محفظه RTL می‌گیرند؛ پیش‌نمایش در GitHub موبایل و دسکتاپ را بررسی می‌کنیم. به CSS یا JavaScript تزریقی اتکا نمی‌کنیم.
- توضیح فارسی با خط فارسی می‌ماند و اصطلاحات رسمی AWS به انگلیسی؛ لینک‌های کوتاه، متن آمیخته را خواناتر می‌کنند.
- بالای هر سند پیوند رفت‌وبرگشت دو زبان ثبت شود.

## اجزای الزامی هر کیت

۱. سؤال و دیاگرام مرجع، همراه با ابهام‌های احتمالی پاسخ.

۲. **گردش بدون ایجاد منابع در تمام سرویس‌های گزینه‌های سؤال** با معرفی تب‌های کنسول و محل توقف پیش از ساخت.

۳. آزمایش کوچک و اختیاری؛ همراه با دلیل روشن تفاوت آن با معماری مرجع.

۴. مقایسه مدل هزینه همه سرویس‌ها با پیوند منابع رسمی و وابستگی به Region/Account.

۵. راهنمای دستی فارسی و انگلیسی، پیش‌بررسی، مسیر Terraform در صورت نیاز، Draw.io، پاک‌سازی و ثبت شواهد.

۶. ادعای اجرای AWS فقط پس از آزمایش واقعی و تأیید جداگانه پاک‌سازی.
